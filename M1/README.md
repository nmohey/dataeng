# Kestrel · Milestone 1 — Sources, Containers, Cleaning

Data Engineering · Winter 2026 · Team: mnf

Pipeline stages 1 and 2 of the Kestrel rogue-agent data platform: **ingest and normalise** nine files in four formats and three clocks, then **clean and integrate** them into one canonical activity table you can trust, with every rejected record carrying one reason from the closed enum and a pointer back to its source.

Everything in this folder runs from a clean clone with `docker compose up`, or on a laptop with a Python virtual environment.

## Run it from a clean clone

### 0. The data

The pipeline reads `kestrel-telemetry-pack-v1` (the unzipped pack, nine files). It looks, in order, at `$KESTREL_RAW_DIR`, then `M1/data/raw/`, then `../kestrel-telemetry-pack-v1` (the pack sitting next to `M1/` at the repository root, which is how this repository is laid out). To use another location, set `RAW_DIR` in `.env` (Docker) or `KESTREL_RAW_DIR` (laptop).

### 1. With Docker (the reproducible way)

```bash
cd M1
cp .env.example .env          # optional: change ports or RAW_DIR
docker compose up -d --build
```

What happens: PostgreSQL 17 starts and becomes healthy, Adminer starts, and the `pipeline` service builds and runs **once**: it reads the pack, writes every curated table to `data/curated/`, loads them into Postgres, and exits. Watch it with

```bash
docker compose logs -f pipeline
```

It takes about a minute. Then open Adminer at <http://localhost:8080> (server `postgres`, user `kestrel`, password `kestrel`, database `kestrel`) and find `canonical_activity`, `fact_rejected_record`, the `dim_*` tables, `siem_flow_correlation`, `m1_sessions` and `m1_metrics`.

Re-run the pipeline by hand, or run the notebooks inside the stack:

```bash
docker compose run --rm pipeline              # re-run ingest → clean → load
docker compose --profile notebook up -d       # Jupyter at http://localhost:8888 (work/notebooks)
docker compose down                           # stop; add -v to drop the database volume
```

### 2. On a laptop (Python 3.12+, no Docker needed for the pipeline itself)

```bash
cd M1
python3 -m venv .venv && source .venv/bin/activate      # Windows: .venv\Scripts\activate
pip install -r requirements.txt
python -m kestrel_m1.pipeline                           # ~1 minute; writes data/curated/
pytest -q tests                                         # 13 unit tests
```

To load the curated tables into a Postgres you started with `docker compose up -d postgres adminer`:

```bash
python -m kestrel_m1.load_postgres                      # uses DATABASE_URL or postgresql+psycopg://kestrel:kestrel@localhost:5433/kestrel
```

To open or re-execute the notebooks (they resolve `M1/` by walking up from their own folder, so they run from any working directory):

```bash
jupyter lab notebooks/                                  # interactive
sh scripts/execute_notebooks.sh                         # re-execute both in place
```

## How the pipeline works

```
agent_activity.parquet ─┐  readers.py  (parquet: schema checked · csv: text · json: flattened · syslog: regex)
tenants/agents/tools/   ─┤      │
model_pricing.csv       ─┤      ▼
sandbox_policies.json   ─┤  entities.py / policies.py   conformed dims, alias maps, Type-2 agent key, flattened policies,
network_flows.csv       ─┤      │                        repaired price windows, overlap rule (latest version wins)
sandbox_audit.log       ─┤      ▼
siem_alerts.json        ─┘  cleaning.py                  normalise (aliases, spellings) → timestamps.py (UTC, per-host offsets)
                                │                        → reasons matrix in enum order → accepted + RejectCollector
                                ▼
                            correlation.py               SIEM ↔ flow on (src_ip, dst_ip, port, |Δt| ≤ 60 s): matched / ambiguous / unmatched
                                ▼
                            canonical.py                 one row shape for all six activity types; validity-window join for
                                │                        policy_version_applied / is_policy_violation; risk_indicators; quality_flags
                                ▼
                            metrics.py                   metrics 1, 2, 8, 9 with denominator, population, late and null policies
                                ▼
                            pipeline.write_outputs       data/curated/*  →  load_postgres.py  →  PostgreSQL
```

Every transformation is a function with inputs and outputs; the notebooks only call them and display what changed. `python -m kestrel_m1.pipeline` is the same sequence without a notebook.

## Notes

* **Nothing is dropped silently.** Every record is either in the canonical table or in the rejects table with its source line and raw payload.
* **`incident_labels.csv` is never read** in this milestone (held-out ground truth, Milestone 2 only); `stream_events.json` is not used either.
* Docker is not required to run the pipeline or the notebooks; it is required for the PostgreSQL/Adminer part of the stack. The Compose file was written against the Lab 2/3 course stack layout (postgres + adminer + a one-off job service).
* Library reuse: pandas, pyarrow, numpy, SQLAlchemy, psycopg, Jupyter/nbconvert, matplotlib, tabulate, pytest.
